INFRA-RED Escuela — plan de migración

De FortiGate 600C a OPNsense + MikroTik

FW-ETEC, el firewall donado y fuera de soporte, se reemplaza por dos equipos con roles separados: OPNsense como borde/filtrado y un MikroTik CCR2004-16G-2S+ como núcleo de ruteo inter-VLAN. Esta página junta el diagrama de la migración y todo lo que hay que sacar del Forti antes de cortar.

Estado: en planificación Equipo saliente: FG600C3912802207 Firmware actual: v5.4.5 build1138 Actualizado: 02/09/2026

La forma de la migración

Hoy un solo equipo hace dos trabajos distintos. Después, cada trabajo tiene su propio equipo — ninguno hace de más.

clave

Un backup de configuración del Forti no sirve para "restaurar" en OPNsense o RouterOS — son formatos completamente distintos. La migración real es leer cada bloque de configuración del Forti abajo y traducirlo a mano a OPNsense (reglas + alias) y a RouterOS (VLANs + rutas). El backup solo sirve como respaldo de emergencia del propio Forti.

Qué extraer del Forti 600C antes del corte

Organizado por bloque de configuración. Todo se puede ver por GUI, pero el camino más rápido y completo es System > Configuration Revisions o CLI vía consola/SSH con show full-configuration.

WAN / internet config system interface

  • IP pública del WAN (o modo DHCP/PPPoE) y máscarainterfaz wan1
  • Gateway y servidores DNSconfig system dns
  • Usuario/contraseña si es PPPoE
  • Segundo enlace o failover, si existeconfig system virtual-wan-link

LAN / VLANs config system interface

  • VLAN ID, subred y gateway de cada zona (admin, aulas, wifi alumnos, wifi docentes, servers)
  • Qué puertos físicos van a cada zonainterfaces tipo switch/hardware switch

DHCP config system dhcp server

  • Rango y lease time por VLAN
  • DNS y dominio entregados por DHCP
  • Reservas fijas: impresoras, APs, servidoresconfig reserved-address

NAT / expuesto a internet config firewall vip

  • Virtual IPs: cualquier servicio publicado (servidor web, cámaras, RDP, mail)
  • Puerto externo → IP:puerto interno de cada regla

Políticas de firewall config firewall policy

  • Listado completo: origen, destino, servicio, acción — es la lógica a replicar en OPNsense
  • Objetos usados: direcciones, grupos, servicios, horariosaddress / addrgrp / service custom / schedule

VPN config vpn ipsec

  • Túneles site-to-site: IP del peer, PSK o certificado, subredes locales/remotas, propuestas fase 1/2
  • SSL-VPN de administración remota, si se usaconfig vpn ssl settings

Perfiles UTM activos config webfilter / ips

  • Qué categorías bloquea hoy el filtro web — piso mínimo a igualar en OPNsense
  • Antivirus / IPS activos y sobre qué políticas

Administración config system admin

  • Usuarios admin y hosts confiables
  • SNMP, si algo lo consulta hoyconfig system snmp community
  • Syslog remoto y servidor NTP

Plan de corte

El orden importa: todo lo que se pueda armar en paralelo, se arma antes de tocar producción.

  1. Preparar en paralelo

    Cargar en OPNsense las reglas y objetos extraídos, y armar las VLANs + trunk en el MikroTik, sin conectarlos todavía a la red en uso. Todo esto se prueba en un puerto libre, no en producción.

  2. Replicar DHCP antes de cortar

    Los scopes y reservas tienen que existir en OPNsense/RouterOS antes de apagar el Forti — si no, los clientes se quedan sin IP al primer renew.

  3. Ventana de corte

    Fuera de horario escolar: desconectar el WAN del Forti y pasarlo a OPNsense; conectar el trunk del MikroTik al switch core. El Forti queda apagado pero cableado como plan B inmediato.

  4. Verificación por VLAN

    En cada zona: salida a internet, resolución DNS, acceso a recursos internos, los port-forwards críticos y las VPN site-to-site si las hay.

  5. Estabilización

    El Forti se mantiene como respaldo frío 2 a 4 semanas. Recién después de ese período sin incidentes se lo da de baja definitivamente.

Plan B — si algo falla en la ventana de corte, revertir es solo recablear WAN y trunk de vuelta al Forti: por eso no se lo apaga del todo hasta confirmar estabilidad.
